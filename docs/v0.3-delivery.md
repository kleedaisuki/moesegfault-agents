# v0.3 delivery and acceptance ledger

## Intended outcome

This release adds Responses alongside the existing Chat Completions API, without
arbitrary historical or workspace forks. It also adds an owner-scoped Space with
managed files and immutable workspace versions. The implementation must remain a
single durable execution engine, not a second harness hidden behind new routes.

The release boundary is working public SDK, dashboard and CLI journeys, not only
serializable response fixtures. Staging is authorized for implementation and
acceptance. Production must only receive the identical accepted artifacts through
the existing Actions promotion gate. Existing v0.1/v0.2 tags, data, pins, credentials
and consumer contracts must remain valid.

## Coordination and review boundaries

Architecture and protocol decisions are recorded in
[the Responses/Space design](responses-spaces-v0.3.md); tests and independent
coverage are recorded in [the verification matrix](v0.3-verification.md).
Implementation owners coordinate shared Rust modules and migration numbers before
editing. Root alone commits, pushes, dispatches delivery and promotes artifacts.

Heavy Rust/Wasm/container checks run in Actions. Local work is restricted to
focused inexpensive probes and genuine client/browser journeys. Failed remote
jobs are investigated from their exact logs/artifacts, not repeatedly restarted
without an explanatory change. Any partial deployment is reconciled at the same
source before switching release candidates.
