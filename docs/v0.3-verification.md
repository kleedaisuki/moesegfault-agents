runtime acceptance; collecting a test or parsing a fixture does not.

## Cost-aware staging gate

Use one bounded large-prefill trajectory, not a duplicate long-context model run.
`test_real_provider_compaction_preserves_pin_and_source_journal` retains its first
Chat Completions turn and continues through Responses with a separate custom
instruction marker. It asserts real compaction, both fixed/custom markers and the
original source-prefix preservation. Existing Chat SDK time/streamed continuation
and deterministic Chat compaction checks remain separate compatibility gates.

The deployed tests require explicit origin/key configuration. Billed model calls
require `MAGENTS_TEST_INFERENCE=1`; Container and compact probes require their
existing workspace/compaction flags. Expensive compact acceptance is staging-only.
`MAGENTS_TEST_REQUIRE_ALL=1` converts any skipped selected journey to suite failure,
so a green deployment cannot silently mean credentials or required capabilities
were absent. The workflow must first match `/healthz.build_id` to the source SHA.

All SDK clients disable automatic retries. A timeout/early EOF is not permission
to submit the same input again; recover using the original response/session ID.
Fixtures discover owned sessions even after observer failure, drain runs, archive
and remove their agent/credentials. Space uploads are deleted through ordinary
APIs. Immutable workspace versions remain retained user data by design, not hidden
test garbage that an administrator should erase behind the user's contract.

The isolated midstream-reset Worker fixture is a deliberate exception to ordinary
resource-drain assertions: it proves that an unknown external result leaves an
unresolved completion receipt. It must not release that receipt by inventing usage.
Its complete synthetic Miniflare database is removed when the suite is disposed;
the corresponding real incident would require evidence-based reconciliation.

## Compiled-artifact diagnosis after CI 40116721317

[Worker CI 40116721317](https://github.com/kleedaisuki/moesegfault-agents/actions/runs/40116721317)
built source `bcdc3f0` and passed 199 native Worker unit checks, but its actual
Worker integration suite failed. The failed run is not release acceptance.
Focused bounded probes reused its downloaded Wasm, without rebuilding Rust or
using paid endpoints:

| Probe | Observation | Classification |
| --- | --- | --- |
| Invalid controls followed by a valid request | Six HTTP 400s then a valid request returning 429 `session_limit`; no accepted response objects | Production admission defect: rejected fresh requests consumed live-session quota. The earlier generic SDK checker assertion was secondary cleanup masking, not a schema mismatch |
| Repeated compact with revised source-item setup | Both real summaries executed; exact fixed/custom layers and old response preserved; no remaining holds; strict SDK checks passed | Original fixture expected compact before the minimum-history guard permitted it. Two source items ensure the intended boundary, without relaxing the two-compaction oracle |
| History-only workload with an adequate configured budget | 111 source entries, complete page reconstruction, authenticated 304, invalid cursors denied, two new delta entries | Original fixture accidentally crossed its compact threshold; history paging must not dispatch an unprovided summary action |
| Unreported provider503 after known no-store/incomplete cases | Exactly one `completion:<failed-response>:round:0` receipt remains reserved at zero BYOK platform amount, no model ledger; D1/DO/R2/Worker observations all settled | Expected unknown-usage provenance, not a leaked resource hold. All other reservation keys remain prohibited |
| Forced OS process-tree crash | Disclosed sequence 4, restored failed terminal 65554, one upstream call, one unresolved completion receipt, zero invented model settlements, strict SDK checks passed | Valid crash primitive. The first overall Windows probe failed only in its final process-exit cleanup race; that isolated harness race was repaired, with full corrected execution still requiring CI |

The history probe measured serialized **synthetic fixture** bodies of 115,111 bytes
for legacy status, 568 bytes for metadata, zero for an unchanged 304 body and 355
bytes for the two-entry delta page. These are actual workerd HTTP-body sizes, not
production traffic, compression, CPU or latency claims.

The shared fixture now preserves primary/provider errors alongside cleanup errors
instead of replacing them in `finally`. Unexpected retained reservations produce
owner-scoped IDs, idempotency keys, amounts and aggregated resource phases. Known
settlement gets a bounded observation window; only explicitly named unknown
completion receipts may remain. Their precise identity and absent ledger are
asserted, not waved away by ignoring every hold.

`unsafeEvictDurableObject` is an idle-eviction API and refuses active references;
it cannot simulate an in-flight crash. The replacement test uses a separate owned
Node/workerd process group and persistent D1/DO files, forcibly terminates it, then
starts a new process against the same data. This cannot poison later tests in the
shared workerd fixture. Ordinary completed-state eviction checks remain in place.

`MAGENTS_WORKER_CASE` optionally selects a named shared-fixture subjourney for
artifact diagnostics; it is unset in the complete CI gate. A focused passing probe
does not replace the complete integration suite or deployed acceptance.
