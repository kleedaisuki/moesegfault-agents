# v0.3.0 — Responses, Space and workspace versions

These notes describe version 0.3.0, not a claim that a particular host has already
been promoted. Use the [published release](https://github.com/kleedaisuki/moesegfault-agents/releases)
and the selected host's `GET /healthz` build to identify what is serving.
[Release readiness](../v0.3-release-audit.md) records the deployment gates and
actual evidence; an Actions artifact is not a published release.

## Call agents through Responses

Use an ordinary OpenAI SDK with the platform base URL, platform API key and an
owned **agent ID** as `model`. Chat Completions and its session-header continuation
remain supported; clients do not have to migrate existing integrations.

Responses adds synchronous, streaming and background execution; typed events;
response retrieval, cancellation, deletion and input-item pagination;
Conversations/items; historical branches; and WebSocket lanes with steering.
Append only new input when continuing a known response or Conversation.

Server/agent instructions, registered tools and selected skill revisions remain
pinned to their session. Response-scoped instructions survive that response's
compaction without becoming the default for later requests. Configure normal
agent compaction as a **percentage** of its model's context budget. Applications
can also use the standard input-token and compact APIs and carry the compacted
window forward.

## Choose where tools run

| Boundary | v0.3 behavior |
| --- | --- |
| Platform harness/workspace | Time, Bash, workspace save/version/restore, code interpretation and its owned artifacts |
| Hosted services | Image generation, web search and Space file search, subject to the selected service's capabilities |
| Caller-local tools | Function/custom and supported computer, shell and patch handoffs remain the client's execution responsibility |
| Remote MCP and programmatic tools | Explicit server/tool policy and approval; programmatic calls retain causal tool/result identity |

Platform language-model routes use DeepSeek or OpenRouter; BYOK remains
available. Image generation uses the configured Seedream 5 route through
OpenRouter or an owned supported image service. Platform web search uses
DeepSeek Search/Fetch; Space file search is a separate first-party capability.
The outer model's key is not implicitly reused for a different paid tool service.

Wire compatibility does not make every upstream model support every option.
Unsupported capabilities fail explicitly rather than being silently ignored or
executed by a different provider. Ordinary Bash and code environments do not
receive provider keys or platform storage credentials.

See [hosted tools](../full-responses-tools.md), [local tool integration](../full-responses-client-tools.md),
[MCP](../full-responses-mcp.md) and [programmatic tools](../full-responses-programmatic-tools.md).

## Manage one account Space

Upload, list, rename, download and delete files from the same Space in adash,
`magents` and the API. Files can be attached to Responses or indexed for file
search. File bytes and identities are immutable; renaming changes display names.

Workspace tools let an agent **save its workspace**, **find saved versions**
across its account and **restore a selected version**. Saved versions are
immutable and downloadable, not user-editable or deletable. Restore preserves
the current state before replacing it. Deleting a file does not erase an
independently retained response artifact or saved workspace version.

See [Space and files](../api.md#files-account-space-and-workspace-versions) and
[data lifetimes](../data-lifecycle.md).

## Use the same account from each client

Adash provides language preferences, light/dark themes and mobile layouts.
`magents --help` and subgroup help progressively expose account, agent, session,
Responses/context, Conversation, container, Space and version management.
Linux and Windows release archives include checksums and actual build metadata.
Verify the downloaded archive before running it; a pre-release Actions artifact
is not a public release asset.

The [three portable skill packs](../../skills/README.md) teach external agents to
use the CLI, integrate the API or contribute to this repository. They are
separate from the [account skill registry](../skills.md) whose selected
instructions are automatically injected and pinned by the service.

## Recovery, accounting and performance

Persist request identities before submitting work. After an uncertain response,
observe the original response or reuse its original idempotency key; do not
create a new operation merely to repair observation. Known paid image results
are retained before local decoding, so receipt or storage recovery does not
repeat image generation. Structured diagnostics preserve the HTTP/protocol,
codec, storage and accounting stage; private recovery bodies are encrypted, not
placed in ordinary telemetry.

Free, Go, Plus and Pro enforce configuration/concurrency limits. Model usage and
platform resources consume versioned API-equivalent credit. BYOK avoids platform
model-provider charges, not workspace, storage or other resource charges.
Subscribe owns subscription activation; returning to adash refreshes the verified
grant rather than trusting a redirect as proof of payment.

The implementation reduces duplicate context copies, checkpoint reads/writes,
stream/render traffic and metering round trips. Recorded byte-count and controlled
latency improvements are scoped measurements, not unmeasured production SLOs.
See [billing](../billing.md), [observability](../observability.md),
[performance](../performance.md) and [programmatic metering](../programmatic-metering.md).
